# 로비 디펜스 아키텍처

## 책임과 수명

[실제 로비 전투 재생](../../../Docs/Previews/LobbyDefense/LobbyDefensePlay.gif) · [테스트 계정의 방어 카드 목록](../../../Docs/Previews/LobbyDefense/LobbyDefenseInventory.png)

확대 지도에서 대기 중인 수비 유닛을 누르면 카드를 선택하면서 해당 유닛의 장기자랑(`Special`)을 한 번 재생한다. 배치·이동 뒤나 공격·장기자랑이 끝난 뒤 15초 동안 계속 대기해도 재생한다. 연속 터치는 재생 중인 동작을 이어가고, 실제 공격은 즉시 장기자랑을 중단한다. 장기자랑은 화면 연출이며 피해·발사·저장 상태를 바꾸지 않는다.

로비 컨트롤러는 활성 계정의 진행 하나를 연다. 순수 C# 모델에서 고정 틱을 계산하고 뷰는 틱 사이의 위치와 동작 프레임을 그린다. 전체 지도는 색상 점으로 진영을 구분한다. 확대 지도는 배치한 수비 유닛의 대기·사격, 침공 몬스터의 이동·봉쇄 공격을 실제 방향으로 표시한다. 마비된 몬스터는 걸음을 멈춘다. [8방향 원화와 클립](../00_Guide/INVADER-ART.md)

현재 규칙에는 진주 수비병·성벽거북과 물방울 젤리·길지기 유령이 등장한다. 진주 수비병은 카드 정의의 `AttackProjectileAddress`로 진주탄을 읽는다. 공격 판정은 모델의 원래 틱에 끝나고 탄은 표적을 따라가며, 그 공격으로 처치하면 발사 당시 위치로 날아간다. 저장 복원 시 진행 중이던 연출은 새로 시작하는 전투 동작부터 표시한다. [규칙표](../../05_Table/LobbyDefenseRules.json) · [AssetManager.cs](../../02_Scripts/Manager/AssetManager.cs)

## 유저 데이터와 보유 유닛

로비 두 번째 탭에서 보유 카드를 세로로 스크롤한다. 같은 종류도 한 장씩 표시되며 카드를 누르면 상세 창에서 등급, 태생 점수, 개별 강화값, 최종 전투 능력치와 종류별 에너지를 확인한다. 변환은 카드 한 장을 소모한다는 확인을 거친다. 성공하면 목록으로 돌아와 지급량과 잔액을 표시하며, 그 종류의 마지막 카드를 소모해도 보유 에너지는 목록 아래에 남는다.

보유 카드와 종류별 에너지는 현재 계정 또는 설치 게스트 단위로 보관한다. 기본 능력치·보정치·등급 경계·변환 지급량은 공통 규칙표에서 읽는다. 카드별 강화와 태생 점수는 계정 저장본에 담는다. [UserDataManager.cs](../../02_Scripts/Manager/UserDataManager.cs) · [규칙표](../../05_Table/LobbyDefenseRules.json)

| 데이터 | 보관할 값 | 사용 시점 |
|---|---|---|
| 공통 유닛 정의 | 종류 ID, 기본 공격·체력·방어, 능력치별 1점당 보정치, 사거리 | 전투 능력치 계산에 쓰는 값을 규칙 데이터에서 읽는다. |
| 유저의 보유 카드 | 보유 카드 ID, 종류 ID, 공격·체력·방어 태생 점수, 획득 시 별 등급, 세 능력치의 개별 강화값 | 한 장당 ID 하나를 발급한다. 같은 종류도 별도 카드로 보관한다. 최초 무료 카드는 계정당 한 번 지급한다. |
| 유저의 에너지 | 유닛 종류 ID, 에너지 잔액 | 해당 종류의 모든 카드가 같은 잔액을 사용한다. |
| 유저의 로비 배치 | 보유 카드 ID, 보드 좌표 | 카드 한 장은 한 칸에 배치한다. 같은 종류도 서로 다른 보유 카드 ID로 구별한다. |

카드 획득 시 세 태생 점수를 각각 정수 0~10에서 독립·균등 추첨하고 고유 등급과 함께 한 번 저장한다. 복원·재배치 때는 저장값을 읽는다. 전투용 능력치를 계산할 때 기본값, 태생 보너스, 선택 카드의 강화값을 사용하고, 대전 시작 편성에는 계산된 수치를 복사한다. [카드 등급·능력치 규칙](LOBBY-DEFENSE.md#유닛-카드와-고유-등급)

카드 변환 시 한 장의 소모와 에너지 지급을 한 건으로 저장한다. 시험값은 변환 1에너지, 강화 1에너지당 선택 능력치 +1이다. 배치 중인 카드도 강화되는 즉시 누적 피해와 공격 시점을 보존해 능력치가 바뀐다. 변환은 회수한 카드에서 가능하다. 마지막 사격 카드는 대체 카드를 고용할 골드가 있을 때 변환할 수 있다.

로비 진입 시 계정을 식별한 뒤 그 유저의 보유 목록과 배치를 함께 연다. 서버 계정은 `Identity.Data.uid`, 오프라인 게스트는 설치별 게스트 식별자를 사용한다. 연결 실패 시 반환하는 공통 UID `dummy_user`는 계정을 구별할 수 없다. 같은 게스트가 온라인 로그인에 성공하면 기존 진행을 한 번 이어받는다. 계정 전환·로그아웃 시에는 이전 세션과 메모리 목록을 닫는다. [IdentityLayer.cs](../../02_Scripts/Manager/UserData/IdentityLayer.cs)

## 배치 한 건의 처리

1. 기획과 화면의 좌표는 (1, 1)부터 시작한다. 모델 배열의 인덱스는 `(행 - 1) × 보드 폭 + 열 - 1`이다. 10×10 전장의 소환 칸은 (1, 5), 출구는 (10, 5)다. 입구를 포함한 1~2열·4~6행의 여섯 칸과 출구에는 유닛·트랩을 놓을 수 없다. 유닛은 한 칸을 막고, 트랩이 있는 칸은 통행할 수 있다.
2. 배치 가능한 칸을 누르면 미리보기용 배열에 배치를 적용한다. 출구에서 역방향 BFS로 빈칸의 거리를 채우고, 입구부터 거리가 1 작은 이웃을 따라가 경로를 표시한다. 동거리 우선순위 초안은 오른쪽 → 위 → 아래 → 왼쪽이다. 확정 배치가 바뀔 때만 실제 거리표를 갱신해 모든 적이 공유한다.
3. 확정 입력은 다음 틱 시작에 수신 순서로 처리한다. 보유 유닛을 선택하면 현재 유저 소유인지, 이미 배치된 유닛인지 확인한다. 배치 가능 여부는 등장 구역과 출구, 점유, 살아 있는 적의 현재 칸과 이동 목적지, 통행 상태를 확인해 결정한다. 새 유닛을 고용하면서 배치하는 경우에는 잔액까지 확인한 뒤 골드 차감·보유 등록·배치를 한 건으로 반영한다. 이미 보유한 유닛의 배치는 무료다.
4. 첫 무료 배치가 확정되면 소환 시계를 시작한다. 전투 중에는 추가 배치, 정비 중에는 이동·회수도 가능하다. 대전에서 모델 상태를 바꾸는 것은 전투 판정뿐이다.

**봉쇄.** 로비에서는 마지막 통로를 막는 배치도 가능하다. 미리보기는 입구와 살아 있는 적 각각의 길을 확인한다. 봉쇄된 적은 출구까지 **돌파해야 할 유닛 수, 총 걸음 수** 순으로 경로를 골라 첫 벽의 인접 칸까지 접근한다. 벽이 무너진 틱에 열린 길로 이동을 예약한다. 대전 출발 때는 입구와 출구가 연결되어야 한다.

## 전투 한 틱

로비에서는 컨트롤러의 `FixedUpdate` 한 번이 모델의 한 틱이다. 대전에선 기존 퍼즐 컨트롤러가 양쪽 방어 모델을 한 번씩 호출한다. 기준은 기존 게임과 같은 초당 50틱이다. 이동·마비·재충전은 정수 틱으로 계산하고, 뷰는 확정된 두 칸 사이만 보간한다. [GameSpec.cs](../../02_Scripts/PuzzleCore/Module/GameSpec.cs)

| 순서 | 판정 |
|---|---|
| 1. 입력·소환 | 대기 중인 배치를 확정하고 그 틱에 예정된 적을 소환한다. 일반 웨이브와 5초 간격 유령의 시계를 따로 둔다. |
| 2. 이동·트랩 | 소환 번호순으로 도착한 칸을 확정한다. 충전된 트랩에 먼저 도착한 일반 적에게 마비를 적용하고 재충전 틱을 예약한다. 유령은 트랩을 소모하지 않는다. 마비 중인 적은 이동과 봉쇄 공격을 쉰다. |
| 3. 전투 | 공격형 방어 유닛은 사거리 내 일반·점수 몬스터 중 출구까지 남은 거리가 짧은 순, 소환 번호순으로 표적을 정한다. 도달 불가 거리는 가장 뒤로 둔다. 공격 주기가 된 적은 막힌 경로의 인접 유닛을 공격한다. 같은 틱의 피해를 대상별로 합산한 뒤 파괴된 유닛의 칸을 연다. |
| 4. 종료·보상 | 체력 0인 적은 한 번만 처치 처리하고, 살아서 출구에 도착한 적은 퇴장시킨다. 이 순서에서는 도착 틱의 사거리 안에서 마지막 공격이 가능하다. 로비 일반 처치는 골드, 대전의 점수 몬스터 처치는 방어 점수에 기록한다. 유령 퇴장의 점수는 0이다. |

일반 웨이브의 모든 일반 적이 처치·퇴장하면 8초 정비에 들어간다. 유령이 남아 있어도 정비할 수 있다. 시제품에서 양수 공격의 한 타 피해는 `max(1, 공격력 - 방어력)`이며, 공격력 0의 피해는 0이다. 파괴된 카드는 다음 정비부터 무료로 복구한다. 정비 중 파괴된 카드는 그 다음 정비에 복구한다. 회수·이동은 누적 피해를 보존한다.

## 로비 저장과 퍼즐 진입

- **이어하기 데이터**에는 저장 형식·규칙 버전, 완료 틱, 다음 몬스터 번호, 배치된 보유 유닛 ID·좌표·잔여 체력, 트랩 위치·재충전 틱, 적의 현재·다음 칸과 도착 틱, 마비·공격 타이머, 웨이브·소환 시계를 담는다. 거리표와 화면 좌표는 복원 시 계산한다. 봉쇄 중에도 앱을 닫을 수 있으므로 그 전투 상태를 그대로 보존한다.
- 규칙 1의 100×10 저장본은 원래 전장에서 유효성을 검사한 뒤 규칙 2의 10×10 좌표로 변환한다. 남은 칸의 유닛·트랩은 같은 열·행과 상태를 유지한다. 사라진 열이나 새 등장 구역·출구에 놓였던 카드는 남은 체력을 보존해 인벤토리로 돌려주고, 그 칸의 트랩은 다시 설치할 수 있다. 새 전장 밖이나 출구에 있던 적은 보상 없이 퇴장한다. 다음 이동 칸만 사라진 적은 현재 칸에서 길을 다시 찾는다. 카드·골드·에너지, 웨이브와 소환 시계는 이어진다.
- `Application.persistentDataPath/LobbyDefense` 아래에 계정별 파일을 저장한다. 고용·배치·카드 변환·강화, 처치 골드는 즉시 저장하고 전투 진행은 5초마다 기록한다. 임시 파일 교체에 실패하면 카드 입력은 취소하고 저장을 재시도한다. 최신 파일이 잠겨 있으면 다시 읽고, 유실됐거나 내용이 손상됐을 때는 백업에서 복구한다. 복원 시 배치의 소유권·중복을 검사한다.
- 대전 준비 성공 후에는 틱과 입력을 멈추고 저장한 뒤 라이프를 차감한다. 저장 실패 시 원인을 표시하고 로비를 재개한다. 라이프 차감 실패 시에도 동결을 푼다. 앱 일시정지 시에도 마지막 완료 틱을 저장한다. 시제품에서 로비를 비운 동안의 경과 시간은 전투에 더하지 않는다. ## 90초 대전에서 퍼즐 리플레이 활용

아래는 대전 연동 설계다. 현재 로비는 대전 진입 전 통행과 저장을 확인하고 복귀 시 이어하기까지 처리한다.

1. 대전 시작 시 로비에 배치된 ID를 현재 유저의 보유 목록과 대조한다. 소유권과 중복을 확인한 편성에서 종류·좌표·당시 능력치와 트랩 정보를 복사해 퍼즐 기록에 붙인다. 상대는 자기 기록의 시작 편성을 쓴다. 경기 중 유닛 피해·파괴는 그 경기 안에서만 적용한다. [LobbyMain.PrepareBattle](../../02_Scripts/Lobby/LobbyMain.cs) · [StageInjection.cs](../../02_Scripts/StageMapTool/StageInjection.cs)
2. 공통 틱에서 내 퍼즐과 상대 리플레이를 진행한 직후 각각의 현재 블록 점수에서 직전 틱 점수를 뺀다. 내 증가분은 상대 방어선에, 상대 증가분은 내 방어선에 전달한다. 기존 퍼즐 입력 재생으로 소환에 필요한 득점 시점을 알 수 있다. 같은 최종 점수라도 경기 초반과 종료 직전의 득점은 몬스터를 공격할 수 있는 시간이 다르다. [PuzzleGameController.FixedUpdate](../../02_Scripts/PuzzleCore/Controller/PuzzleGameController.cs) · [ReplayController.CurrentScore](../../02_Scripts/PuzzleCore/Controller/ReplayController.cs)
3. 디펜스 전투는 이번 대전 중 한 번 진행한다. 종료 시 양쪽의 블록 점수와 처치 점수로 결과를 확정하고 결과 화면에 표시한다. 전적을 다시 표시할 때는 확정된 결과 요약을 읽는다. 소환·이동·공격 이력과 틱별 점수열은 저장 대상에서 제외한다. 재도전은 같은 시작 편성으로 새 경기를 진행한다.
4. `ReplayData.finalScore`는 퍼즐 재생 검증용 블록 점수다. 퍼즐 재생기는 편성이 없는 이전 기록도 읽을 수 있다. 디펜스 대전 상대는 편성이 있는 호환 퍼즐 기록에서 고른다. 호환 상대가 없는 첫 판은 자신의 퍼즐 기록과 시작 편성을 남긴다. [ReplayData.cs](../../02_Scripts/PuzzleCore/Module/ReplayData.cs) · [ReplayStorage.Load](../../02_Scripts/PuzzleCore/Module/ReplayStorage.cs)

## 구현 순서와 인수 기준

| 순서 | 구현 범위 | 통과 기준 |
|---|---|---|
| 1. 보유와 배치 | 최초 카드 지급, 순수 C# 보드, 후보 조회·확정 | 재접속해도 무료 카드는 한 장이다. 미보유 카드 또는 동일한 카드 ID의 이중 배치는 거절한다. 빈 보드 9걸음, (5, 5) 배치 후 11걸음이며 미리보기와 실제 경로가 같다. |
| 2. 첫 고용 | 세션 틱, 일반 적, 공격형 방어 유닛, 골드 | 첫 세 마리 처치로 15골드를 얻는다. 고용 후 0골드와 보유 두 기가 함께 복원된다. 중복 확정·저장 실패 재시도·회수 후 재배치로 추가 차감이나 중복 지급이 생기지 않는다. |
| 3. 봉쇄와 트랩 | 길막 유닛, 5초 주기 유령, 파괴·재탐색, 재충전 | 15초 동안 유령 세 마리 소환, 떨어진 곳에서 벽까지 접근, 유령 둘의 피해 합산, 벽 파괴 후 이동 재개. 트랩은 첫째·셋째 일반 적에게만 발동하고 유령은 통과한다. |
| 4. 이어하기 | 저장·복원, 확대 조작, 90초 대전 진입 | 처치 직후와 이동 중에 각각 저장한다. 복원 후 같은 틱까지 진행하면 연속 실행과 위치·잔액·웨이브가 같고, 저장 실패 시 라이프가 보존된다. |
| 5. 대전 | 양쪽 배치 고정, 퍼즐 득점에 따른 상대편 소환, 종료 결과 집계 | 서로 다른 편성으로 4,500틱을 진행해 각 득점이 반대편 소환 계산에 한 번 반영되고 처치 가점은 추가 소환을 일으키지 않는지 확인한다. 결과 화면 값은 해당 경기의 집계와 일치하고 기존 퍼즐 기록은 원래 종료 점수로 재생된다. |

계정 전환 검증에서는 A의 유닛을 배치한 뒤 B로 로그인한다. B는 A의 유닛을 배치할 수 없어야 하며, A로 돌아오면 보유 카드·종류별 에너지·골드·배치를 복원해야 한다. 같은 계정의 궁수 두 장 중 한 장의 공격을 강화한 뒤 다시 열어 공용 잔액이 한 번만 줄고, 선택 카드의 공격 강화값만 바뀌며, 두 카드의 태생 점수와 등급이 보존되는지 확인한다.

**첫 고용의 기준 사례.** (5, 5)에 사거리 2칸, 공격력 4, 공격 주기 1초인 진주 수비병을 배치한다. 3·6·9초에 소환된 체력 12의 일반 몬스터를 각각 7·10·13초에 처치해 15골드를 얻는다. 실제 시작 카드의 공격 태생 점수 0~10을 각각 적용했을 때 같은 배치에서 첫 고용에 걸린 시간은 11~13초였다.

**후속 기획 결정.** 로비 플레이테스트에서 파괴 카드의 무료 복구 시점과 에너지 지급·소모량을 조정한다. 대전 연동 전에는 점수당 소환 수·시점, 일반 적 출구 감점, 제한 시간 종료 시 생존 적과 동점 처리를 정한다. 직선 이동 9초를 기준으로, 우회와 트랩이 90초 경기의 도착 수에 미치는 영향을 시험한다. [기획서의 검증 시나리오](LOBBY-DEFENSE.md)
